# Troubleshooting

Common issues and their solutions when running FlowMind AI. Each issue includes the symptoms, root cause, and step-by-step resolution.

## Common Issues

| # | Issue | Cause | Solution |
|---|-------|-------|----------|
| 1 | **ChromaDB permission errors** — `chromadb.db: Permission denied` or `Cannot create directory` | The ChromaDB persist directory (`./chroma_db`) is not writable by the current process user. In Docker, the volume mount may have incorrect ownership or permissions. On HuggingFace Spaces, the directory may not exist at all. | 1) Run `chmod -R 755 backend/chroma_db` on the host machine. 2) If using Docker, verify the volume mount target matches the `CHROMA_PERSIST_DIR` env var. 3) On HuggingFace Spaces, ensure the Dockerfile includes `RUN mkdir -p /app/chroma_db && chmod 777 /app/chroma_db`. 4) Check that the directory is not owned by root when the container runs as a non-root user. |
| 2 | **Groq API rate limits** — HTTP 429 `Too Many Requests` or `Rate limit exceeded` errors in the backend logs | The Groq free tier enforces request-per-minute limits (approximately 30 req/min for Llama 3.3 70B). This can also occur when multiple queries arrive simultaneously or during burst traffic. The built-in retry logic may exhaust its attempts. | 1) The `GroqClient` has built-in retry with exponential backoff (3 retries, starting at 1s). 2) If errors persist, increase `CONFIDENCE_THRESHOLD` in `.env` to 0.6+ to reduce LLM calls (more queries get escalated instead). 3) Upgrade to a paid Groq plan for higher rate limits. 4) Reduce `TOP_K_RESULTS` (default 3) to make prompts shorter and faster. 5) Switch to a faster/cheaper model like `llama-3.1-8b-instant` if accuracy is acceptable. |
| 3 | **Twilio webhook not receiving messages** — WhatsApp messages sent to the Twilio number but n8n shows no incoming executions | The webhook URL configured in the Twilio Console is incorrect, the n8n workflow is inactive, or an intermediate proxy (Cloudflare Worker) is rejecting valid requests. | 1) Verify the webhook URL in Twilio Console > WhatsApp > Sandbox Settings matches your n8n URL (e.g., `https://your-n8n.com/webhook/whatsapp`). 2) Ensure the WhatsApp Query Handler workflow is activated (green toggle) in n8n. 3) If using a Cloudflare Worker, check the Worker logs for rejection reasons. 4) Verify `TWILIO_AUTH_TOKEN` in Worker secrets matches your Twilio token exactly. 5) Twilio requires HTTPS — ensure your n8n instance is behind an SSL-terminating proxy. |
| 4 | **CORS errors in frontend** — Browser console shows `Access-Control-Allow-Origin` errors when the dashboard tries to call the API | The backend's `CORS_ORIGINS` setting does not include the frontend's origin, or the Vite dev proxy is not properly configured to forward `/api` requests. | 1) For local development, set `CORS_ORIGINS=["*"]` in the backend `.env` file. 2) For production, set `CORS_ORIGINS=["https://flowmind-ai.vercel.app"]` (or your actual frontend domain). 3) The Vite dev server is configured to proxy `/api` to `localhost:8000` automatically — verify this in `vite.config.ts`. 4) If using a custom backend URL, ensure `VITE_API_URL` in the frontend `.env` is set correctly. |
| 5 | **Docker networking issues** — n8n cannot reach the backend, or the backend cannot connect to ChromaDB in another container | In Docker Compose, services communicate via the service name as hostname. Using `localhost` inside a container refers to the container itself, not other containers on the network. | 1) Always use service names for inter-container communication: `http://backend:8000` (not `http://localhost:8000`). 2) The `docker-compose.yml` already sets `FASTAPI_URL: http://backend:8000` for the n8n service. 3) Verify both services are on the same Docker network (the default Compose network). 4) Use `docker compose logs <service>` to check for connection refused errors. 5) If using custom networks, ensure all services are attached. |
| 6 | **n8n workflows not triggering** — Workflows are imported but do not execute when webhooks are called or schedules fire | Workflows may be imported but not activated. The webhook URL path may not match what the external service is calling. n8n may be in "testing" mode where webhooks use a different path. | 1) Open each workflow in the n8n editor and verify the **Activate** toggle is ON (green). Inactive workflows have a gray toggle. 2) Check that the webhook path in the workflow node matches the URL you are calling. 3) Note: in n8n, active webhook paths are prefixed with `/webhook/` in production mode but `/webhook-test/` in testing mode. 4) For scheduled workflows, verify the cron expression is correct and that the n8n timezone matches your intent. 5) Check n8n's execution log for any failed or pending executions. |
| 7 | **PDF upload fails** — 400 Bad Request `Invalid file type`, 413 `File too large`, or 500 `PDF parsing failed` | The upload endpoint only accepts `.pdf` files under 10 MB. Other formats (DOCX, TXT, PNG, JPG) are rejected. Large PDFs exceed the size limit. Some PDFs use non-standard encoding that fails to parse. | 1) Ensure the file is a valid PDF (check with `file document.pdf` — should say "PDF document"). 2) Convert other formats to PDF first: `libreoffice --headless --convert-to pdf input.docx`. 3) For files over 10 MB, split into smaller files or increase `MAX_FILE_SIZE` in `backend/app/routes/upload.py`. 4) For PDFs with scanned images (no selectable text), the upload will succeed but queries will return low confidence because there is no text to index — consider OCR preprocessing. 5) Check backend logs for the specific error from `PyPDF2` or the embedding step. |
| 8 | **Low confidence on all queries** — Every query returns `escalated: true` or confidence below 0.3 | Documents may be too short (insufficient context per chunk), chunking parameters may split sentences mid-way and lose meaning, the embedding model may not suit the domain, or the documents may not actually contain relevant information. | 1) Increase `CHUNK_SIZE` to 800-1000 characters for longer context per chunk (default is 500). 2) Adjust `CHUNK_OVERLAP` to 50-100 for less fragmentation at chunk boundaries. 3) Ensure your documents have substantial text content — documents that are mostly images, tables, or charts will produce poor chunks. 4) Try a different embedding model: set `EMBEDDING_MODEL=BAAI/bge-small-en-v1.5` in `.env`. 5) Temporarily lower `CONFIDENCE_THRESHOLD` to 0.3 for testing to see what confidence values you actually get. 6) Re-upload documents after changing chunking parameters (old chunks are not automatically re-chunked). |
| 9 | **Telegram notifications not sending** — Escalation alerts or daily summaries never arrive on Telegram | The `TELEGRAM_BOT_TOKEN` may be incorrect, the `TELEGRAM_ADMIN_CHAT_ID` may be wrong or formatted as a string, or the bot and admin may not have started a conversation yet. | 1) Verify the bot token by visiting `https://api.telegram.org/bot<TOKEN>/getMe` in your browser — you should see your bot's name. 2) Send a message to your bot in Telegram first, then call `https://api.telegram.org/bot<TOKEN>/getUpdates` to find your numeric `chat_id`. 3) Ensure `TELEGRAM_ADMIN_CHAT_ID` is a plain number (not quoted in `.env`). 4) Check n8n execution logs for Telegram API error messages. 5) If the bot was created recently, ensure it is not restricted. |
| 10 | **Google Sheets logging not working** — Conversations are not being recorded in the spreadsheet, or the n8n Google Sheets node fails | The Google service account does not have access to the target spreadsheet, the `GOOGLE_CREDS_JSON` environment variable is malformed or missing, or the sheet does not have the required column headers. | 1) Share the target Google Sheet with the service account email (found in the `client_email` field of your credentials JSON). Set permission to "Editor". 2) Ensure `GOOGLE_CREDS_JSON` is valid JSON — common issues: extra outer quotes, missing braces, newlines breaking the string. Test by pasting the value into `python -c "import json; json.loads(open('creds.json').read())"`. 3) Verify the sheet has the exact column headers: `Timestamp`, `User Phone`, `Question`, `Answer`, `Confidence`, `Escalated` (for the Conversations sheet). 4) Check that `GOOGLE_SHEETS_ID` matches the long ID in the spreadsheet URL. 5) If Google Sheets is not configured at all, the backend falls back to CSV logging in the `logs/` directory — check there for `.csv` files. |

## Diagnostic Checklist

If you're experiencing an issue not listed above, run through this checklist:

1. **Check backend logs**: `docker compose logs backend --tail=100` or `python -m uvicorn app.main:app --log-level debug`
2. **Check n8n executions**: Open n8n UI > Executions tab to see failed workflows and error messages.
3. **Test the API directly**: `curl http://localhost:8000/api/health` to verify the backend is responding.
4. **Check environment variables**: `docker compose exec backend env | grep -i groq` to verify env vars are loaded.
5. **Verify Docker networking**: `docker compose exec n8n curl -s http://backend:8000/api/health` to test cross-container connectivity.
6. **Restart everything**: `docker compose down && docker compose up -d` to clear any stale state.
